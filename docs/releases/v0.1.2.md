# Notes de version — v0.1.2

> Préparé par ⚒️ Gimli (branche `chore/ressource-cli-0.41.0`, 2026-09-06), à l'usage
> d'Aragorn pour la commande de tag. **Aucun tag n'a été posé par cet agent** — le tag
> déclenche `release.yml` (matrice 4 plateformes + publication), geste réservé au décideur.

## Contexte du bump

`main` embarquait la ressource CLI `@naonedge/iakaframe` en `0.40.0` depuis la v0.1.1. Le
dépôt sœur `iakaframe` a publié `v0.41.0` : les étapes 3/4 de la chaîne d'installation
(`iakaframe install`) — poser IakaCockpit et iakaFrameGUI — couvrent désormais **Linux**
(AppImage) et **Windows** (`.exe` NSIS `currentUser`), en plus de macOS. Le cadrage AR-P5(a)
de `specs/instructions/pilotage-reel-facade-contrat-machine.md` impose de remonter cette
ressource épinglée à chaque release de la façade : c'est l'objet exclusif de ce lot.

## Preuve de la couverture Linux/Windows côté moteur (v0.41.0)

Ce que « installeur unifié complet sur Windows et Linux » veut dire concrètement, et ce qui le
prouve — re-vérifié en lecture seule par ⚒️ Gimli (`gh run view`, `gh api compare`), pas repris
tel quel du rapport d'un autre agent :

- **Run `33997947501`** (`banc-etapes-3-4.yml`, `iakaframe`, `2026-09-05T23:10:29Z`,
  `headSha=e34c1af9…`) : job `banc (ubuntu-latest)` **`success`** ; job
  `banc (windows-latest)` **`failure`**, échoue à l'étape « Mesures reelles Windows
  (etapes 3/4) ». C'est ce run, **avant correctif**, qui a mesuré le défaut de rollback NSIS
  (`uninstall.exe /S` sans `_?=<InstallLocation>` : code retour `0` mais clé de registre
  encore présente).
- **Run `33999564308`** (même workflow, `2026-09-05T23:46:48Z`, `headSha=3baf20ec…`) : job
  `banc (windows-latest)` **`success`** — 16 mesures dont 15 `PASS` (1 `NON-MESURE` : UAC sur
  compte non-administrateur, gate humain déclaré). C'est le run **après** le correctif
  d'uninstall synchrone.
- **Le tag `v0.41.0` est postérieur aux deux runs et INCLUT le correctif** :
  `gh api repos/iakasju/iakaframe/compare/3baf20ec5a773f11c82bfe63471ad1a252b20588...v0.41.0`
  → `{"ahead_by": 8, "behind_by": 0, "status": "ahead"}`. Le `headSha` du run 2
  (post-correctif) est donc un **ancêtre direct** de `v0.41.0` (0 commit derrière, 8 devant) :
  la ressource remontée dans ce lot embarque bien le correctif de rollback Windows mesuré vert,
  pas seulement le code d'avant le fix.

Autrement dit : « complet sur les trois OS » signifie ici « les étapes 3/4 s'exécutent et se
défont sur Linux et Windows, mesuré vert sur runner CI réel, correctif de rollback inclus dans
la version embarquée » — **pas** « recette faite sur un poste Windows/Linux réel », qui reste
un gate humain (§ ci-dessous).

- **Correctif incident** : la note de sécurité (`fixtures/vitrine-locale.json`,
  `macos-notarisation`) citait en dur `iakaInstall_0.1.1_aarch64.dmg` entre backticks — la
  garde anti-dérive de la vitrine (CA-10, `scripts/lib/vitrine.mjs`) lit tout nom d'artefact
  entre backticks comme une promesse du README ; au bump, ce nom figé sur une version passée
  devenait une fausse promesse non dérivable de la table courante. Reformulé sans répéter de
  nom de fichier versionné, la mesure historique (v0.1.1, 2026-09-05) reste dite intacte.
- **Fixture `fixtures/flux-apercu.ndjson` ré-enregistrée** contre la ressource 0.41.0 (rejeu
  réel `--dry-run --events` en bac à sable, `--target-claude`/`--apps-dir`/`--backup-dir` sous
  scratchpad, aucune écriture réelle constatée). 74 lignes, `fin`/`ok:true`, comme avant.
  Diff champ par champ (hors horodatage) contre l'ancienne fixture 0.40.0 : **7 des 74 lignes
  changent** (1, 2, 3, 4, 6, 8, 11). Sur ces 7, **3 (lignes 1, 3, 4) ne changent que le numéro
  de version** ; les **4 autres (lignes 2, 6, 8, 11) changent aussi de chemin** —
  `reservoir.embarqueDir`/`installMjsPath`/`provenance` (ligne 2), le
  `sourceRetenue.pourquoi` de l'annonce de l'étape 2 (ligne 6), et deux lignes de log délégué
  `Kits  :`/`Kit   :` (lignes 8, 11). **Motif du changement de chemin** : l'ancienne fixture
  (0.40.0) avait été enregistrée avec `--root` pointé sur une extraction du tarball dans un
  répertoire scratch (`.../scratchpad/release/extrait/package`) ; ce rejeu-ci pointe `--root`
  directement sur `src-tauri/resources/cli` — la ressource **telle qu'embarquée en place** par
  `npm run embarquer`, qui est aussi ce que fait par défaut `scripts/rejeu-vivant.mjs`
  (`RESSOURCE = join(ROOT, "src-tauri", "resources", "cli")`). Ce n'est **pas** un changement
  de comportement du CLI 0.41.0 : c'est un changement de la commande de capture entre les deux
  enregistrements. Le reste du flux (les 67 lignes non listées, dont les étapes 3/4 sur
  `darwin-arm64`) est **structurellement identique** — aucune annonce Linux/Windows sur cette
  machine, attendu : les étapes 3/4 restent conditionnées à la plateforme réellement détectée.
  **Aucun test ne dépend de la VALEUR de ces chemins.** Vérifié : `grep -rn "embarqueDir\|
  installMjsPath\|Kits  :\|Kit   :" scripts/__tests__ src/__tests__` ne remonte rien — aucun
  test n'assert un chemin littéral. Et `scripts/__tests__/rejeu-flux-apercu.test.mjs`, qui lit
  cette fixture, ne compare **que par auto-référence** : le modèle rejoué par le réducteur
  contre l'événement `reservoir`/`etape-annoncee` **de la même fixture** (`vue.sourceRetenue`
  == `evt.sourceRetenue`, `etats[idx].provenance` == `evt.provenance`, etc.) — jamais contre
  une valeur figée en dur dans le test. Que la fixture porte un chemin scratch ou un chemin
  projet ne change donc rien à son verdict.
